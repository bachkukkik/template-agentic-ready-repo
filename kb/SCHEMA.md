# Knowledge Base — Schema & Conventions

> **Spec:** this KB follows the llm-wiki skill **strictly** —
> <https://github.com/NousResearch/hermes-agent/blob/main/skills/research/llm-wiki/SKILL.md>
> Where this file and that spec disagree, the spec wins; fix this file.

## Purpose

Funnel stages 2–3 (see *Document Funnel* in `AGENTS.md`). The KB is the authoritative
source for project semantics, architecture decisions, data models, and research
findings. PRDs and code reference KB entries via `[[wikilinks]]`.

**Two layers, one direction:**

| Layer | Path | Owner | Rule |
|-------|------|-------|------|
| 1 — raw | `raw/` | humans + ingest | Immutable. Add new files or archive; **never edit**. Any format. |
| 2 — pages | `concepts/`, `entities/`, `comparisons/`, `queries/` | the `llm-wiki` agent | **Never hand-written.** Regenerated by `/llm-wiki ./kb/` after `raw/` changes. |

## Directory Structure

```
kb/
├── SCHEMA.md        # This file — domain conventions, structure rules, tag taxonomy
├── index.md         # Sectioned catalog with one-line summaries
├── log.md           # Append-only chronological action record
├── raw/             # Layer 1: immutable source material
│   ├── articles/    #   web clippings
│   ├── papers/      #   PDFs, specs, academic papers
│   ├── transcripts/ #   meeting notes, interviews
│   └── assets/      #   images, diagrams
├── entities/        # Layer 2: people, orgs, products, models, vendors
├── concepts/        # Layer 2: topics and ideas
├── comparisons/     # Layer 2: side-by-side analyses
├── queries/         # Layer 2: filed query results
└── _archive/        # Superseded raw + pages, original path structure preserved
```

## Invocation

```bash
# after adding or archiving anything under kb/raw/
/llm-wiki ./kb/
```

`WIKI_PATH` is this repo's `kb/` — always pass `./kb/` explicitly so the skill does
not default to `~/wiki`.

## File Naming

- Lowercase kebab-case: `transformer-architecture.md`
- No spaces in filenames
- One concept per file
- Split pages over ~200 lines into sub-topics with cross-links

## Required Frontmatter

Layer-2 wiki pages:

```yaml
---
title: Page Title
created: YYYY-MM-DD
updated: YYYY-MM-DD
type: entity | concept | comparison | query | summary
tags: [taxonomy-defined tags]
sources: [raw/articles/source.md]
confidence: high | medium | low        # optional
contested: true                        # optional
contradictions: [conflicting-page]     # optional
---
```

Layer-1 raw sources:

```yaml
---
source_url: https://example.com
ingested: YYYY-MM-DD
sha256: <hex digest of body content only>
---
```

## Confidence Ratings

- **high** — multiple independent sources verified
- **medium** — single source + reasonable inference
- **low** — unverified, needs validation (flagged by lint)

## Wikilinks

Use `[[page-name]]` (filename without `.md`). **Minimum 2 outbound wikilinks per
page.** Syntheses drawing on 3+ sources carry provenance markers:
`^[raw/articles/file.md]`.

## Page Creation Thresholds

Create a page when the entity/concept appears in 2+ sources, or is central to one
source, **and** it meets the 2-wikilink minimum. Do not create pages for passing
mentions, footnote references, or anything outside this repo's scope.

## Session Initialization (before any ingest or query)

1. Read `SCHEMA.md` — domain and conventions
2. Read `index.md` — page inventory
3. Scan the last 20–30 entries of `log.md` — recent context

Skipping this produces duplicate pages, missed cross-references, and schema violations.

## Ingest Workflow

1. Capture the raw source into the right `raw/` subdirectory
2. Add frontmatter including `sha256` of the body content
3. Discuss key takeaways
4. Search existing pages to prevent duplicates
5. Create/update layer-2 pages that meet the thresholds
6. Cross-reference — 2+ outbound wikilinks per page
7. Update `index.md` alphabetically
8. Append the action to `log.md`

Re-ingest compares `sha256`: identical → skip; drifted → flag and update.

## Contradictions

1. Check dates — newer generally supersedes older
2. Genuinely contradictory → record both positions with dates and sources
3. Mark `contradictions: [conflicting-page-name]` in frontmatter
4. Flag for user review in the lint report

Never silently overwrite.

## Archiving

Unused or superseded material goes to `_archive/`, it is **not deleted**:

1. Move the file into `_archive/`, preserving its path structure
2. Remove it from `index.md`
3. Update linking pages — replace the wikilink with plain text + "(archived)"
4. Append the archive action to `log.md`

## Lint

Audit for: orphaned pages, broken wikilinks, index completeness, frontmatter
validation, off-taxonomy tags, stale content (>90 days), contradictions,
`confidence: low` pages, source drift via `sha256` mismatch, oversized pages
(>200 lines), tag consistency, log rotation (>500 entries).

## Conventions

- Ephemeral state goes in `scratchpads/`, never here
- Nothing tracked may cite a `scratchpads/` path as evidence
- Confirm before mass-updating 10+ pages
- Rotate `log.md` past 500 entries
- Keep pages scannable — under 30 seconds to read
